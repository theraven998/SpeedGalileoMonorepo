Implementa una cola offline-safe para el escaneo de asistencia en SpeedGalileo,
protegiendo contra pérdida de datos por cold-start del backend (Render free
tier duerme tras 15min sin tráfico, primer request tras eso tarda 30-50s) o
cortes de red momentáneos en el celular del profesor en portería.

CONTEXTO DEL PROYECTO
- Monorepo: ~/Proyects/GradoDiegui (github.com/theraven998/SpeedGalileoMonorepo)
- Frontend: code/frontend, Next.js 16 App Router, TODO client components ("use
  client"), deploy estático (output: "export") a Firebase Hosting
  (https://speedgalileo-galileo.web.app)
- Backend: code/backend, Express+TS+Mongoose, deploy en Render free
  (https://speedgalileomonorepo.onrender.com), Mongo Atlas M0
- Cliente API único: code/frontend/src/lib/api.ts — función request<T>() que
  envuelve fetch, lanza ApiError en !res.ok
- Endpoint crítico a proteger: POST /api/attendance/scan (profesor escanea QR
  del estudiante en /porteria, code/frontend/src/app/porteria/page.tsx) —
  perder este write significa asistencia no registrada, sin forma de saber
  que se perdió.
- El backend YA es idempotente para este endpoint: un estudiante solo puede
  tener un registro por día, retry duplicado devuelve 409 "ya tiene registro
  hoy" (ver code/backend/src/contro,
  función scanQr). NO agregues idema 409 como
  éxito silencioso en el retry (ya quedó registrado, probablemente por un
